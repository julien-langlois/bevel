# Translations and regional formats

`bevel-i18n` translates an interface whose source text is English, and writes numbers, sizes
and measures the way the user's region does. It has no egui dependency.

## Catalogs and lookup

The catalogs are tab-separated files per locale, in the format of
[craft-i18n](https://github.com/storytold/craft-i18n): one shared catalog and one per app.
The app's `build.rs` embeds them as a static table; the crate itself never reads files.

```rust,ignore
include!(concat!(env!("OUT_DIR"), "/bevel_i18n.rs")); // pub static BEVEL_I18N: &bevel_i18n::Embedded

pub static I18N: LazyLock<bevel_i18n::I18n> = LazyLock::new(|| {
    let offered: Vec<&str> = LANGUAGES.iter().map(|l| l.code).collect();
    let (i18n, problems) = bevel_i18n::I18n::new(BEVEL_I18N, &offered); // parses nothing yet
    problems.iter().for_each(|p| log::warn!("translation catalog: {p}"));
    i18n
});

let label = I18N.t(lang, "Merge requests");
```

- **Offered locales.** `I18n::new` takes the languages the app offers, so it never offers one
  its interface isn't ready for. An embedded locale that isn't offered still serves as a
  fallback (`pt` for an offered `pt-br`).
- **Fallback** goes locale by locale: `pt-br` → `pt` → the English source text. A missing
  translation is never an error; it shows the English.
- **Lookups:** `t` (plain), `tc` (with a context such as `menu`), `tid` (a command id),
  `trn` (a count, with the language's plural forms), `fmt` (`{name}` placeholders).
- **Lazy parsing.** Nothing is parsed at startup; a locale is parsed the first time a lookup
  reaches it. `I18n::check_all()` parses everything, for a test.

## Plurals and numbers

Plural rules and number formats come from CLDR, through ICU4X:

- `trn` picks the plural form for a count (Arabic has six, Japanese one); `trn_decimal`
  picks it from the digits shown, so English "1.0 files" is plural.
- `Format` writes numbers for a region: `integer` (`1.234.567` in German, `12,34,567` in
  India), `number`, `percent`, with the region's digits (`١٬٢٣٤٫٥` in Egypt) or Latin ones.
- `Format::parse` reads what people type or paste: any decimal digits, the region's
  separators, and an unambiguous `.` or `,`. Input that doesn't fit is an error, never a guess.
- `file_size` and `measure` write `1.5 MB`, `12 px` in the interface language.

## The region is not the language

`Region` holds how numbers, dates and measures are written, apart from the interface
language: an English interface in Poland writes `1 234,5`. `Region::system()` reads it from
Windows' regional settings, Apple's current locale, or `LC_NUMERIC`, `LC_TIME`,
`LC_MEASUREMENT` and `LC_PAPER` on Unix; `Region::from_setting` takes the app's saved choice.

## Bidirectional text

When a message or a value inserted into it is right to left, `fmt` wraps each inserted value
in an isolate, so a Latin file name in an Arabic sentence (or the reverse) cannot reorder the
words around it. `fmt_plain` and `strip_isolates` give text without the marks, for file names
and logs. `direction(tag)` says whether a language reads right to left: see
[Right-to-left interfaces](direction.md).

## Search and sorting

- `Folder` folds text for case- and accent-insensitive search, with a map back to the original
  for highlighting: `ﬁ` finds `fi`, `Layer ١٢` finds `layer 12`.
- `Collator` (feature `collate`) sorts by the locale's rules, with numbers compared by value
  (`Layer 2` before `Layer 10`).

## The system locale

`I18n::system_lang()` matches the system's preferred languages against the offered ones once:
`LANGUAGE`, `LC_ALL`, `LC_MESSAGES` and `LANG` on Unix, the preferred languages on macOS and
Windows, the browser's on the web. A script is never crossed: `sr-Latn-RS` picks `sr-latn`,
never Cyrillic `sr`.
